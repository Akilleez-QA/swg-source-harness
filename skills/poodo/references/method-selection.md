# Operation selection

Start with the unresolved question. Select the smallest operation that can answer it or expose what evidence is missing. A named method earns its place only if its output could change the orientation, decision, action, or verification.

| Need | Operation | Optional examples | Common failure |
|---|---|---|---|
| Expose frames | Diverge | premortem, scenario analysis, morphological analysis | decorative possibilities with no discriminator |
| Establish reality | Observe | direct inspection, comparison, process boundary map | proxy treated as outcome |
| Explain an effect | Causal discriminate | competing hypotheses, fault tree, change analysis, controlled comparison | chronology or correlation presented as cause |
| Anticipate failure | Stress | hazard analysis, FMEA, red team | scoring unsupported by evidence |
| Choose | Compare | decision tree, sensitivity analysis, robust choice | arithmetic hiding judgment |
| Learn through action | Experiment | reversible trial, DOE, PDCA | activity treated as success |
| Sustain | Monitor | control signal, review trigger, rollback threshold | measurement without response rules |

## Selection rule

1. State the question the operation must answer.
2. State what artifact or observation it will produce.
3. State how that result could change the decision.
4. Name its main limitation or coupling.
5. Add another operation only for a different cognitive job or an orthogonal check.
6. Stop when another operation is unlikely to change the decision.

Use Quick, Standard, or Deep depth according to stakes and uncertainty. Depth changes evidence and testing effort, not the number of headings or methods.
