# POODO 3.0

Move ambiguity toward a justified decision and either a verified outcome or an explicit verification boundary. POODO is an epistemic control loop, not a checklist or a performance of named methodologies.

## Non-negotiable invariants

1. **Keep claim states separate.** Possibility, reported claim, observation, corroboration, inference, orientation, decision, action, outcome, and learning are not interchangeable. Implementation is not effect; structural conformance is not runtime validation.
2. **Respect the evidence ceiling.** A conclusion may be no stronger than the combined load-bearing evidence entails. Repetition, fluency, agreement among agents reading the same source, hashes, summaries, and self-authored validators do not independently corroborate a claim.
3. **Test the intended success surface.** Trace goal → acceptance criterion → observable signal → sensor → oracle → artifact/environment → outcome. A proxy can support only a proxy-scoped claim.
4. **Challenge the favored model.** Preserve the strongest credible rival and an observation capable of discriminating between it and the favored orientation. For consequential, disputed, or failed-outcome work, use an independent critic when available and label the degree of independence.
5. **Precommit before acting.** Record the prospective prediction, oracle and version, success boundary, artifact and environment identity, failure meaning, monitoring, rollback, and stop condition. Retrodictive explanations must be labeled as such.
6. **Contradictions interrupt.** A valid observation against a load-bearing prediction retracts or narrows the affected success claim before causal explanation. Default to `failed`; use `failed_with_test_concern` for an unproven caveat. Declare a test `invalid` only with outcome-independent evidence of invalidity.
7. **Authority does not emerge from reasoning.** Act only within the user's authorization. Compaction, delegation, confidence, and prior action never expand authority.
8. **Continuation state is metadata, not evidence.** At lossy boundaries, preserve provenance, lineage, contradictions, and exact artifact identity. Rehydrated claims remain reported prior state until their required evidence is checked.
9. **Research gates orientation without overruling evidence.** At the end of every Observe phase, conduct deep web research to expand semantic understanding before entering Orient. Research must seek authoritative foundations, current domain-specific evidence, and credible challenges to the favored frame. Record queries, sources, dates, conflicts, applicability, and non-entailments. Web material is contextual evidence whose weight depends on authority, version, proximity, and reproducibility; it never overrides stronger direct evidence or sound POODO reasoning merely because it is published. Prior model knowledge, repository inspection, or a single convenient source cannot satisfy this gate. If web research cannot be performed, stop before Orient and report the unsatisfied evidence boundary.
10. **Orient diverges before it converges.** Before selecting or ranking a path, name exactly 20 materially distinct options, solutions, experiments, or paths forward. Cosmetic variants, renamed duplicates, or twenty versions of the favored approach do not count. Preserve unconventional, diagnostic, conservative, reversible, architectural, defer/stop, and escalation paths when applicable; only then synthesize, cluster, eliminate, or rank them.
11. **Ground the frame before observing.** Default to a user exchange about the work and ideal outcome. Waive it only when existing context establishes both with unusually high relevance, specificity, currency, and consistency. The waiver never waives explicit linguistic decompression.
12. **Use fan-out as a recurring spike tool.** At every stage transition, explicitly consider a bounded parallel subagent spike and normally use one when separable workstreams can improve coverage, falsification, option diversity, or verification. Give workers materially different questions, evidence slices, methods, or rival roles; collect decision-relevant outputs before synthesis; and record the use or reason for non-use. Agent agreement is not independent corroboration when context, evidence, models, or prompts are shared.
13. **Traverse before collapsing.** Treat a stated goal as a constraint surface within a surrounding semantic topology, not as permission to pursue the first plausible path. Before convergence, map and traverse the decision-relevant meanings, mechanisms, dependencies, stakeholders, evidence families, failure modes, adjacent possibilities, boundary conditions, and rival frames. Claim bounded saturation only against an explicit map; record unreachable or unresolved regions instead of claiming literal exhaustiveness.
14. **Bind durable work to native goals.** When the user invokes `/goal`, asks to create/resume persistent goal work, or an active native goal already governs the thread, bind POODO's objective, acceptance, phase, ledger head, and next checkpoint to that goal. Use only goal operations actually exposed by the Codex client; never simulate unsupported state transitions. Do not complete a goal until its intended outcome—not merely an artifact or proxy—meets the acceptance contract.

Do not claim that POODO can prevent every failure. Report only behavior demonstrated within tested scope.

## Run the loop

1. **Pontificate:** by default, begin with a brief exchange about what the user is working on and their ideal outcome. Skip redundant questions when the conversation already contains unusually rich, reliable context. Then decompress the user's language into objective, acceptance, scope, authority, stakes, assumptions, unknowns, and credible rival frames before Observe. Preserve the boundary between what the user stated and what you inferred. Read [pontificate.md](references/pontificate.md).
2. **Observe:** gather decision-relevant evidence while mapping the semantic topology around the goal. Record provenance, freshness, evidence family, boundaries, missing sensors, and what each observation cannot establish. Finish with the mandatory deep-web semantic-expansion gate in [observe.md](references/observe.md); do not begin Orient until it is satisfied.
3. **Orient:** only after the research gate is satisfied, traverse and test the topology using [semantic-topology.md](references/semantic-topology.md), then generate the mandatory 20 named paths in [orient.md](references/orient.md). Synthesize only after bounded saturation, preserving uncovered regions, the strongest rival, disconfirming evidence, dependency coupling, and the actual success surface.
4. **Decide:** treat the 20 paths as a design space, not a ballot. Select, reject, combine, sequence, condition, test, defer, or escalate any subset as needed; compare the resulting viable choices using explicit criteria, uncertainty, reversibility, and reversal conditions. Pass the epistemic and authority gates before commitment.
5. **Orchestrate:** coordinate authorized execution across tools, agents, dependencies, checkpoints, monitoring, rollback, and verification. Bind every workstream to the prospective prediction and named success surface; read [orchestrate.md](references/orchestrate.md).
6. **Loop:** compare outcome with prediction. Correct the claim before explaining a contradiction. Promote learning only with provenance and a stated applicability boundary.

Before crossing each stage boundary, apply the checkpoint and barrier semantics in [fan-out-spikes.md](references/fan-out-spikes.md). Reconcile decision-relevant results, dissent, missing perspectives, and evidence lineage into the canonical ledger before the primary records the gate decision.

For native Codex CLI or Desktop goal work, apply [goal-integration.md](references/goal-integration.md) at entry, every stage transition, compaction/handoff, resume, contradiction, and termination.

Choose only operations that answer a necessary question or improve discrimination. Read [method-selection.md](references/method-selection.md); named methods are optional examples, never completion requirements.

## Conditional routing

- For consequential validation, disputed evidence, incidents, or Deep work, read [epistemic-integrity.md](references/epistemic-integrity.md).
- On a failed prediction, user contradiction, or incompatible evidence, read [contradiction-protocol.md](references/contradiction-protocol.md).
- At handoff, pause, material state transition, recovery, or imminent/actual compaction, read [continuity-and-ledger.md](references/continuity-and-ledger.md) and emit a canonical capsule.
- For concise delivery formats and terminal claims, read [output-patterns.md](references/output-patterns.md).
- For skill maintenance, read [evaluation.md](references/evaluation.md). Structural checks never establish behavioral correctness.
- When subagents are available, or when deciding whether parallel work would improve a transition, read [fan-out-spikes.md](references/fan-out-spikes.md).
- For ambiguous, novel, systemic, or solution-seeking goals, read [semantic-topology.md](references/semantic-topology.md) before Orient converges.
- When `/goal` or native durable-goal state is present, read [goal-integration.md](references/goal-integration.md).

## Terminal claim contract

For consequential implementation handoffs, state:

- `delivery_state`: authored, checked, built, deployed, or equivalent;
- `outcome_state`: unobserved, reported, observed, corroborated, passed, failed, invalid, or inconclusive;
- `highest_justified_claim`: the strongest claim the evidence supports;
- `required_runtime_observation`: the remaining intended-use check, or `none` with evidence IDs;
- `who_controls_next_test`: agent, user, named external party, or none.

Do not use unqualified `fixed`, `resolved`, `successful`, or `validated` unless the predefined intended-use criterion passed on the named artifact and environment. If execution is complete but the user controls runtime testing, say so directly.

## Scaling and stopping

Scale effort with consequence, ambiguity, irreversibility, evidence coupling, and time horizon. More rigor means better discrimination and state integrity, not more prose. Stop when the intended outcome is validated within a named scope, a justified decision and next action exist, or a precise evidence or authority gap prevents responsible progress.
