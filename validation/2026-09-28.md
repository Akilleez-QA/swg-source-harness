# Hands-on validation — September 28, 2026

Tested the v0.1.0 GitHub release ZIP after checking its published SHA-256, then repeated the workflow with v0.1.1 fixes. Platform: local Linux/Python; Windows and macOS were not exercised.

## Contributor workflow

Created a disposable Git repository containing a deliberately incorrect reward calculation and two executable regression checks. Both failed on the baseline. Fixed the calculation, committed it, reran the checks successfully and captured their actual output as evidence. Initialized/filled the task and ran preflight and verification from the downloaded harness.

Observed: complete evidence accepted as unsigned local preflight; failed checks rejected by `check`; tampered reports and dirty/new-commit candidates rejected by `verify`. Command text in task JSON was not executed. Read-only `inspect` also correctly identified the existing SWG Source server checkout at 34092239a7519984e77a20ebbd6efecb48a44510 as clean. No game builds or runtime tests were performed.

The first fixture attempt encountered Python's timestamp/size bytecode cache after a rapid same-size source edit. That was a fixture problem, not a harness regression. Repeated in a fresh disposable repository with bytecode writes disabled; preserved the initial attempt separately.

## Defects found and repaired

- `verify` exited zero for a checksum-valid, current report with a failed check. It now returns 1 and explicitly says preflight is incomplete.
- Relative evidence paths were interpreted against the caller's directory, despite the instructions specifying absolute paths. They now receive an explicit rejection.

Added regression cases and observed both fail before implementation changes. All 16 CLI tests pass after the fixes; the full disposable contributor workflow also passes with the expected rejection statuses.

## Important boundary confirmed

The collector accepts a fabricated success narrative if its required fields and local file digest are valid. This is expected under the current self-report contract, but means v0.1.x is not the intended project admission filter. A checksum can also be recomputed by an editor; it is not a signature. Every report remains `review_eligible: false` and `signed: false`.

Trusted execution, project-owned profiles, signer isolation and maintainer adoption remain necessary before using this as a required review gate. These tests do not establish reduced reviewer effort, model compatibility, gameplay correctness or resistance to hostile repositories.
